## 二、Phase 1 新增：`employees` 员工白名单

> 状态：**已部署 + 已联调通过**（v0.1-phase1, 2026-06-28）

### 用途

整个系统的身份基础表。所有人首次进入小程序时被强制跳到激活页，输入姓名 + 部门进行匹配；匹配成功则把当前微信 openid 写入该条记录，之后这个微信号就是这个员工。

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 | 示例 |
|---|---|---|---|---|---|
| `_id` | string | 自动 | 系统 | 主键，云数据库自动生成 | `8a3f...` |
| `name` | string | ✅ | HR | 员工姓名 | `"李妙言"` |
| `dept` | string | ✅ | HR | 部门（枚举见下） | `"项目部"` |
| `role` | string | ✅ | HR | `"employee"` 或 `"admin"` | `"admin"` |
| `openid` | string | 系统填 | 激活云函数 | 微信 openid，首次激活时由 `whoAmI` 写入；未激活为 `""` | `"oXyz_abc..."` |
| `activatedAt` | Date \| null | 系统填 | 激活云函数 | 激活时间戳，未激活为 `null` | `2026-06-28T08:30:00.000Z` |
| `active` | boolean | ✅ | HR | 是否启用（离职=false 即冻结，不删数据） | `true` |

### 部门枚举

```
项目部
运行检修部
综合管理部
枢纽管理部
安全技术部
财务资金部
```

> 前端激活页 / HR 后台员工管理页都用这 6 个值作为下拉框选项。
> 写入数据库时必须是上面这 6 个字符串之一，云函数 `whoAmI` 会校验。

### 角色枚举

| 值 | 含义 | 权限 |
|---|---|---|
| `employee` | 普通员工 | 只能登录小程序、参加考试 |
| `admin` | 管理员（HR/老板/部门负责人等） | 小程序 + Web 后台都能登录；HR 后台可建考试、看分数、管员工 |

### 唯一性 / 业务约束

- **(name, dept)** 组合在 active=true 范围内**应当唯一**（同名同部门会导致激活时无法判定，需 HR 在录入时避免）
- **openid 全表唯一**（除空字符串外）— 防止一个微信号绑两条员工记录
- `activatedAt` 为 `null` 说明从未激活过；非 null 说明已激活
- `active=false` 的员工：路由守卫拦截，登录小程序时提示「账号已停用」

### 索引建议（手动在云控制台创建）

| 索引名 | 字段 | 唯一 | 用途 |
|---|---|---|---|
| `idx_openid` | `openid` | 否 | 路由守卫用 openid 反查员工 |
| `idx_name_dept` | `name + dept` | 否 | 激活时按姓名+部门匹配 |

> 不设唯一索引是因为云数据库唯一索引对空值处理较敏感；改成业务层校验更稳。

### 权限设置（重要）

云控制台 → 数据库 → employees → 权限设置：**仅创建者可读写**。

> 普通用户**不能直接读写**这张表，所有访问必须经过云函数（云函数以管理员身份运行，绕过权限）。这是安全核心。

## 三、Phase 1 新增：`adminSessions` HR 后台登录会话

### 用途

HR 在 Web 后台登录的会话票据表。流程：
1. HR 用手机打开小程序 → 进入「管理后台入口」 → 调云函数 `adminLogin` 生成 6 位码（5 分钟有效）→ 屏幕显示
2. HR 在浏览器输入「姓名 + 部门 + 6 位码」→ 调云函数 `adminVerify` 校验 → 返回 24 小时 token
3. 后续所有 Web 后台请求带 token，云函数 `adminGuard` 校验

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 |
|---|---|---|---|---|
| `_id` | string | 自动 | 系统 | 主键 |
| `code` | string | ✅ | adminLogin | 6 位随机数字码 |
| `openid` | string | ✅ | adminLogin | 申请登录的微信 openid |
| `employeeId` | string | ✅ | adminLogin | 对应的 employees 记录 \_id |
| `token` | string \| null | 系统 | adminVerify | 校验通过后生成的 24h token；未校验为 `null` |
| `codeExpireAt` | Date | ✅ | adminLogin | 6 位码到期时间（=创建+5min） |
| `tokenExpireAt` | Date \| null | 系统 | adminVerify | token 到期时间（=校验+24h） |
| `createdAt` | Date | ✅ | adminLogin | 创建时间 |
| `consumed` | boolean | ✅ | adminVerify | 6 位码是否已被使用（一次性） |

> 这张表在 Phase 4（HR Web 后台）才真正用上，Phase 1 先设计好留位。

## 四、修改命名/扩展约定

- 后续新加字段，写入云函数 / HR 后台 / 数据库设计.md 三处同步
- 字段命名统一 camelCase
- 时间字段统一用 Date 类型（云数据库原生支持），不要存字符串
- 任何「业务标志位」都用 boolean，避免 `0/1` 这种容易歧义的值
