## 二、Phase 1 新增：`employees` 员工白名单

> 状态：**已部署 + 已联调通过**（v0.1-phase1, 2026-06-28）

### 用途

整个系统的身份基础表。所有人首次进入小程序时被强制跳到激活页，输入姓名 + 部门进行匹配；匹配成功则把当前微信 openid 写入该条记录，之后这个微信号就是这个员工。

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 | 示例 |
|---|---|---|---|---|---|
| `_id` | string | 自动 | 系统 | 主键，云数据库自动生成 | `8a3f...` |
| `name` | string | ✅ | HR | 员工姓名 | `"李妙言"` |
| `dept` | string | ✅ | HR | 部门（枚举见下） | `"项目部"` |
| `role` | string | ✅ | HR | `"employee"` 或 `"admin"` | `"admin"` |
| `openid` | string | 系统填 | 激活云函数 | 微信 openid，首次激活时由 `whoAmI` 写入；未激活为 `""` | `"oXyz_abc..."` |
| `activatedAt` | Date \| null | 系统填 | 激活云函数 | 激活时间戳，未激活为 `null` | `2026-06-28T08:30:00.000Z` |
| `active` | boolean | ✅ | HR | 是否启用（离职=false 即冻结，不删数据） | `true` |

### 部门枚举

```
项目部
运行检修部
综合管理部
枢纽管理部
安全技术部
财务资金部
```

> 前端激活页 / HR 后台员工管理页都用这 6 个值作为下拉框选项。
> 写入数据库时必须是上面这 6 个字符串之一，云函数 `whoAmI` 会校验。

### 角色枚举

| 值 | 含义 | 权限 |
|---|---|---|
| `employee` | 普通员工 | 只能登录小程序、参加考试 |
| `admin` | 管理员（HR/老板/部门负责人等） | 小程序 + Web 后台都能登录；HR 后台可建考试、看分数、管员工 |

### 唯一性 / 业务约束

- **(name, dept)** 组合在 active=true 范围内**应当唯一**（同名同部门会导致激活时无法判定，需 HR 在录入时避免）
- **openid 全表唯一**（除空字符串外）— 防止一个微信号绑两条员工记录
- `activatedAt` 为 `null` 说明从未激活过；非 null 说明已激活
- `active=false` 的员工：路由守卫拦截，登录小程序时提示「账号已停用」

### 索引建议（手动在云控制台创建）

| 索引名 | 字段 | 唯一 | 用途 |
|---|---|---|---|
| `idx_openid` | `openid` | 否 | 路由守卫用 openid 反查员工 |
| `idx_name_dept` | `name + dept` | 否 | 激活时按姓名+部门匹配 |

> 不设唯一索引是因为云数据库唯一索引对空值处理较敏感；改成业务层校验更稳。

### 权限设置（重要）

云控制台 → 数据库 → employees → 权限设置：**仅创建者可读写**。

> 普通用户**不能直接读写**这张表，所有访问必须经过云函数（云函数以管理员身份运行，绕过权限）。这是安全核心。

## 三、Phase 1 新增：`adminSessions` HR 后台登录会话

### 用途

HR 在 Web 后台登录的会话票据表。流程：
1. HR 用手机打开小程序 → 进入「管理后台入口」 → 调云函数 `adminLogin` 生成 6 位码（5 分钟有效）→ 屏幕显示
2. HR 在浏览器输入「姓名 + 部门 + 6 位码」→ 调云函数 `adminVerify` 校验 → 返回 24 小时 token
3. 后续所有 Web 后台请求带 token，云函数 `adminGuard` 校验

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 |
|---|---|---|---|---|
| `_id` | string | 自动 | 系统 | 主键 |
| `code` | string | ✅ | adminLogin | 6 位随机数字码 |
| `openid` | string | ✅ | adminLogin | 申请登录的微信 openid |
| `employeeId` | string | ✅ | adminLogin | 对应的 employees 记录 \_id |
| `token` | string \| null | 系统 | adminVerify | 校验通过后生成的 24h token；未校验为 `null` |
| `codeExpireAt` | Date | ✅ | adminLogin | 6 位码到期时间（=创建+5min） |
| `tokenExpireAt` | Date \| null | 系统 | adminVerify | token 到期时间（=校验+24h） |
| `createdAt` | Date | ✅ | adminLogin | 创建时间 |
| `consumed` | boolean | ✅ | adminVerify | 6 位码是否已被使用（一次性） |

> 这张表在 Phase 4（HR Web 后台）才真正用上，Phase 1 先设计好留位。

## 四、修改命名/扩展约定

- 后续新加字段，写入云函数 / HR 后台 / 数据库设计.md 三处同步
- 字段命名统一 camelCase
- 时间字段统一用 Date 类型（云数据库原生支持），不要存字符串

## 五、Phase 2 新增：`assessments` 正式考试事件

> 状态：**Phase 2 在建**（v0.2-phase2 目标），起草于 2026-06-28

### 用途

每条记录对应 HR 在后台发布的一场考试。和现有的 `exam` 集合（题库分类）**完全分开**，避免数据语义混乱。

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 | 示例 |
|---|---|---|---|---|---|
| `_id` | string | 自动 | 系统 | 主键 | 自动生成 |
| `title` | string | ✅ | HR | 考试标题 | `"2026 年 6 月项目部摸底考试"` |
| `subjectId` | string | ✅ | HR | 关联 `subjects._id`，从这个科目随机抽题 | `"001001"` |
| `startTime` | Date | ✅ | HR | 开考时间，早于此时间禁止进入考场 | `2026-06-28T10:00:00.000Z` |
| `duration` | number | ✅ | HR | 答题时长（**分钟**） | `60` |
| `questionCount` | number | ✅ | HR | 随机抽题数量 | `30` |
| `passingScore` | number | ❌ | HR | 及格分（可为空）；展示用 | `60` |
| `targetDepts` | array<string> | ✅ | HR | 目标部门（**空数组 = 全员**） | `["项目部"]` |
| `visible` | boolean | ✅ | HR | 是否发布；未发布的员工看不到 | `true` |
| `createdBy` | string | ✅ | 系统 | 创建者 `employees._id` | `"d43898..."` |
| `createdAt` | Date | ✅ | 系统 | 创建时间 | `2026-06-28T08:00:00.000Z` |

### 业务规则

- `questionCount` 不能超过 `questions` 集合里对应 `subjectId` 的题目总数（云函数 `enterExam` 内做兜底）
- 同一员工对同一 `assessmentId` 只能 enter 一次（由 `examEnrollments._id` 复合键保证）
- `startTime` 一旦发布**不可修改**（云函数会拒）
- `targetDepts` 留空数组（不是 null）表示「全员」

### 权限

**仅创建者可读写** —— 所有访问走云函数。

## 六、Phase 2 新增：`examEnrollments` 答卷记录

> 状态：**Phase 2 在建**

### 用途

整个防作弊机制的核心。员工进入考场瞬间，云函数把抽到的题目 + 官方答案 + 截止时间**冻结**进这张表，整场考试只读这份快照，前端拿到的题目**永远不带 answer 字段**。

### 主键设计

`_id = "{assessmentId}_{openid}"`（或模考时 `"mock_{随机串}_{openid}"`）—— 保证同一人对同一场考试**只能有一条记录**，从源头杜绝多卷作弊。

### 字段定义

| 字段名 | 类型 | 必填 | 写入方 | 说明 |
|---|---|---|---|---|
| `_id` | string | ✅ | enterExam | 复合主键 |
| `assessmentId` | string | ✅ | enterExam | 关联 `assessments._id`；模考时为空字符串 |
| `isMock` | boolean | ✅ | enterExam | 是否模拟考试 |
| `openid` | string | ✅ | enterExam | 答题人 |
| `employeeId` | string | ✅ | enterExam | 关联 `employees._id`，便于 HR 后台展示姓名 |
| `status` | string | ✅ | enterExam / submitExam | `'in_progress'` / `'submitted'` |
| `questions` | array | ✅ | enterExam | 题目快照（每项不含 answer 字段） |
| `answersOfficial` | array | ✅ | enterExam | 官方答案数组，**仅 submitExam 读取**，前端读不到 |
| `answers` | object | ✅ | saveDraft / submitExam | 用户作答，`{ qid1: 'A', qid2: ['B','C'] }` |
| `score` | number\|null | ✅ | submitExam | 得分；未判分前为 null |
| `total` | number | ✅ | enterExam | 总题数（=questionCount） |
| `startedAt` | Date | ✅ | enterExam | 进入考场时间 |
| `submittedAt` | Date\|null | ✅ | submitExam | 提交时间；未提交为 null |
| `deadline` | Date | ✅ | enterExam | startedAt + duration，**永不变**，防续考拖延 |
| `switchCount` | number | ✅ | saveDraft | 前后台切换次数（合规计数，不强制干预） |
| `clientLastSavedAt` | Date | ✅ | saveDraft | 最后一次草稿保存时间，心跳监控用 |

### 权限

**仅创建者可读写** —— 普通员工无法直接读，连自己的 answers 都要通过云函数。

### 题目快照剥离规则（核心安全点）

云函数 `enterExam` 从 `questions` 集合抽到的原始记录形如：
```json
{
  "_id": "01", "title": "微信的创始人是？",
  "options": [
    { "code": "A", "content": "马化腾", "value": "0" },
    { "code": "B", "content": "张小龙", "value": "1" }
  ]
}
```

写入 enrollment 前必须**双重剥离**：
1. `questions[i].options[j]` **移除 value 字段**（保留 code 和 content）
2. 另存到 `answersOfficial[i]`：`{ qid, correctCodes: ['B'] }`

这样前端拿到的题目对象完全无法推断答案，达到「答案不下发」原则。
